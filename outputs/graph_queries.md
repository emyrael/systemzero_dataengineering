## 4. Who are each vendor's top three customers by recognised spend?

## 5. How many customers does each vendor reach, and what share of all buyers is that?

```sql
SELECT name AS vendor,
       array::len(array::distinct(->supplies->product<-purchased[WHERE recognised = true]<-customer)) AS customers_reached,
       math::round(100 * array::len(array::distinct(->supplies->product<-purchased[WHERE recognised = true]<-customer))
           / array::len(array::distinct((SELECT VALUE in FROM purchased WHERE recognised = true)))) AS influence_pct,
       math::round(revenue_generated) AS revenue_generated
FROM vendor
ORDER BY customers_reached DESC, vendor
```

Influence = distinct customers reached through the vendor's products, as a share of all buying customers. A three-hop traversal with an edge filter; revenue alone would rank a vendor with a few large buyers above one with broad reach.

## 6. Do invoice line costs match the catalog cost of the products they bill?

```sql
SELECT (in<-billed<-vendor.name)[0] ?? '(unknown vendor)' AS vendor,
       count() AS lines_checked,
       count(math::abs(math::abs(unit_cost) - out.cost) <= 0.01) AS cost_matches
FROM invoice_item
WHERE out.cost != NONE
GROUP BY vendor
ORDER BY vendor
```

Each `invoice_item` edge links a line to the product it bills, so the check is a comparison across the edge (`unit_cost` vs `out.cost`; credit lines carry the negated cost). Every checkable line matches. Lines whose product is not in the catalog have no edge and are counted at load time.

## 8. Is a vendor's on-time payment performance related to how well its products sell?

```sql
SELECT name AS vendor,
       math::round(math::mean(->billed->invoice[WHERE is_credit_note = false AND due_date <= $as_of]
           .map(|$i| IF $i.payment_status = 'paid' AND $i.payment_date <= $i.due_date THEN 100 ELSE 0 END))) AS on_time_pct,
       math::round(math::sum(->supplies->product<-purchased[WHERE recognised = true].net_revenue)) AS product_sales
FROM vendor
ORDER BY vendor
```

Both measures come from traversals: invoices billed by the vendor, and sales of the products it supplies. SurrealQL has no correlation function, so the report computes Pearson r from these rows (`pearson_r`). With ten vendors the coefficient is indicative, not significant.
